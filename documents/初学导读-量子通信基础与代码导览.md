## 1 先建立直觉：量子通信到底在干什么

这一节不用公式，只讲画面。

### 1.1 一个比特怎么被「量子地」发出去

传统通信：Alice 想发 `0`，就发一束代表 `0` 的光。Eve 半路截下来看一眼，抄一份，原样发给 Bob——谁都不知道。

量子通信换了个玩法：**Alice 用单个光子的「状态」来承载比特**，而且准备了两套互不兼容的暗号：
- **Z 基**：`0°` 偏振代表 0，`90°` 代表 1
- **X 基**：`45°` 偏振代表 0，`135°` 代表 1

这就是 BB84 协议的全部出发点。本工程里「选基」对应参数 `p.Pza_u`、`p.Pzb`（[params.m:54](+qkd/params.m#L54)）。

### 1.2 关键：Bob 只能选一套暗号来读

Bob 收到光子时**不知道 Alice 用的是哪个基**，只能随机挑一套去测。会发生两种结果：

- 挑对了（概率一半）：测得准，结果和 Alice 发的一致。
- 挑错了（概率一半）：结果完全随机，跟 Alice 发的没半点关系。

### 1.3 对基：把「猜错的那一半」扔了

测量完，Alice 和 Bob 通过**公开信道**互相通报：「我用的是 Z 基」「我也是 Z 基」。
双方一致的那些脉冲就留下，不一致的（约一半）扔掉。这叫**基比对 / 筛选**。

代码里体现得很直白：Z 基的概率是 `p.Pza_u`，X 基就是 `1 - p.Pza_u`（[estimate.m:69-72](+qkd/estimate.m#L69-L72)）。
所谓 `P_u·P^A_{Z|u}·P^B_Z`（[keyRateAt.m:58](+qkd/keyRateAt.m#L58)）就是「既用了信号态、Alice 又选了 Z 基、Bob 也选了 Z 基」的比例——只有这些脉冲有资格变成密钥。

### 1.4 为什么 Eve 一定会露馅

Eve 想在中间偷走比特，会撞上三条物理定律：

1. **不知道基**：她测得出来什么，取决于她猜的基。猜错的概率就有一半。
2. **不能克隆**：量子不可克隆定理——她没法把光子复制一份留着，必须动原件。
3. **测量会扰动**：只要她碰了，Bob 那边就会多出原本不该有的错误。

所以 **误码率就是 Eve 留下的脚印**。这正是本工程里 X 基存在的意义：**X 基几乎不参与成码，专门用来数脚印**（`e1Ux`，[estimate.m:118](+qkd/estimate.m#L118)）。

### 1.5 筛完的比特还不是密钥，得花两笔钱

筛后比特里还有两类问题：一是少量误码（器件不完美造成的）；二是 Eve 可能已经掌握了部分信息。
于是还要做两件事：

- **纠错**：把双方不一致的比特找出来对齐，代价是**要公开一部分信息**。
- **隐私放大**：把 Eve 可能知道的那部分「挤压掉」，方法是做哈希压缩。

本工程的密钥率公式就是「收入 − 支出」，对应 [keyRateAt.m:58-60](+qkd/keyRateAt.m#L58-L60)：

```
R = P_u·P^A_{Z|u}·P^B_Z · { P1^u·Y~1^{Z,L}·[1 - H2(e~1^{X,U})] − Q_u·f·H2(E_u) }
    └── 资格系数 ──┘   └──── 隐私放大后的收入 ────┘   └── 纠错开销 ──┘
```

其中 `H2` 是二进制熵（[keyRateAt.m:54](+qkd/keyRateAt.m#L54)），作用是把「误码比例」换算成「要花多少比特」。
`f = 1.16` 表示实际纠错比理论极限多花了 16%（[params.m:59](+qkd/params.m#L59)）。

**到这里，教科书部分的量子通信就讲完了。** 下面三件事才是工程真正的难点。

## 2 现实世界的三个坑（三个任务都在跟它们打交道）

### 2.1 坑一：没有理想的「单光子源」，只能用衰减激光

教科书假设「一次恰好送出一个光子」。现实里拿不到这种理想光源，最便宜的办法是把激光**衰减到很弱**，
叫弱相干光源（WCS）。问题是：衰减后的脉冲里，光子数是**随机的**，服从泊松分布：

```
P_n = e^{-l} · l^n / n!        （代码：estimate.m:64）
```

`l` 就是参数里的「光强」`u`、`v`——注意它**不是光子数，是平均数**（[params.m:47](+qkd/params.m#L47)）。
取 `u = 0.5` 算一下就知道现实多骨感：

| 脉冲里有几个光子 | 概率 |
| --- | --- |
| 0 个（真空） | 60.7% |
| 恰好 1 个（安全） | 30.3% |
| 2 个 | 7.6% |
| 3 个及以上 | 约 1.4% |

也就是说：**只有三成的脉冲是真正安全的，还有将近一成的脉冲带了两个以上光子。**

### 2.2 坑二：多光子 = 小偷的缝隙（PNS 攻击）

脉冲里有 2 个光子时，Eve 可以按光子数下手：拿走一个自己留着，把另一个放过去。
Bob 照常收到、照常不出错，**误码率一点没涨**——等 Bob 公开基之后，Eve 拿手里那个光子一测，全知道了。
这叫**光子数分裂（PNS）攻击**。

注意这条攻击的恶劣之处：§1.4 里「误码率会暴露 Eve」的推理**在这里失效了**。
所以多光子脉冲带来的不是「多一点误码」，而是「安全证明直接崩掉」。

### 2.3 坑二的解法：诱骗态（本工程的核心思想）

既然单光子看不见，那就**让它自己暴露**：

Alice 随机切换光强——大部分脉冲用强的（信号态 `u`），一部分用弱的（诱骗态 `v`），还有一部分干脆不发光（真空态 `P0`）。
光强是随机的、只有 Alice 知道，Eve 分不清手里这个脉冲是强还是弱，只能按「平均行为」去偷。

于是出现了关键一步：**同样是偷，对强脉冲和弱脉冲的「伤害比例」是一样的**。
写下两个强度的收支账，两个方程、两个未知数，就能反推出单光子究竟贡献了多少。
这就是 (3.28)（[estimate.m:107](+qkd/estimate.m#L107)）在做的事：

```
Y1 下界 = [P2^u·Qv - P2^v·Qu + (…真空项…)·Y0] / (P1^v·P2^u - P1^u·P2^v)
           ↑诱骗态取下界  ↑信号态取上界   ↑暗计数取上界        ↑只要 u>v，这个分母就恒正
```

再看 (3.29)（[estimate.m:118](+qkd/estimate.m#L118)）：先算出「X 基收到的错误总数」，扣掉「真空态瞎猜贡献的那部分错误」，
剩下的都算单光子头上，再除以单光子数量，就得到单光子误码率 `e1`。

**这里有个必须养成的好习惯**：从头到尾，每一个不确定的量都往「对自己不利」的方向取——
算密钥用的量取下界，算误码用的量取上界。宁可把性能报低，也不能把安全性报高。
这条原则在 [estimate.m:107-119](+qkd/estimate.m#L107-L119) 每一行都能看到。

### 2.4 坑三：脉冲数是有限的，「估」出来的数字有水分

理论上你可以发无穷多个脉冲，把概率估得无限准。实际上题目只给 `N = 1e8 ~ 1e10`。
用有限个样本估出来的 `Q*` 一定会偏离真值 `Q`，所以必须说清楚：

> 我有 `1-ε` 的把握（`ε = 1e-7`），真值落在 `[下界, 上界]` 这个区间里。

怎么划这个区间，就是三种方法的全部区别（`fluct.m`）：

| 方法 | 余量公式 | 一句话理解 | 代码 |
| --- | --- | --- | --- |
| 高斯 | `Δ = γ·√(Q/N)`，`γ=√2·erfcinv(ε)≈5.33` | 样本一多就近似正态分布，留 5.33 个标准差 | [fluct.m:77](+qkd/fluct.m#L77) |
| 霍夫丁 | `Δ = √(n_W·ln(1/ε)/2)/N` | 不假设分布，只要求有界，最坏情况，余量最宽 | [fluct.m:90](+qkd/fluct.m#L90) |
| 切尔诺夫 | 下界 `√(2x·ln(16/ε⁴))`、上界 `√(2x·ln(ε^-1.5))` | 专为计数设计，**上下不对称** | [fluct.m:159-160](+qkd/fluct.m#L159-L160) |

记住一条因果链，三张图就都能解释了：

> **余量越宽 → 扣掉的越多 → 算出的密钥率越低 → 最远能传的距离越短。**

## 3 三个题目的物理层拆解

三个任务共用同一条计算链，**区别只在「哪些参数固定、哪些被优化」**。

### 3.1 一条链路四步（先把这个记住）

不管哪个任务，每个距离点上都是同样四步（`gain.m` 前四行代码就是前两步）：

| 步骤 | 算什么 | 式子 | 代码 |
| --- | --- | --- | --- |
| ① 剩多少 | 光飞 L 公里后透过率 | `η = η_d·10^(-αL/10)` | [gain.m:42](+qkd/gain.m#L42) |
| ② 收得到吗 | 增益（Bob 报「收到」的概率） | `Q_l = Y0 + 1-e^(-ηl)` | [gain.m:52](+qkd/gain.m#L52) |
| ③ 收错了吗 | 量子误码率 | `E_l = (e0·Y0 + e_d·(1-e^(-ηl)))/Q_l` | [gain.m:60](+qkd/gain.m#L60) |
| ④ 能剩多少密钥 | 扣掉纠错、扣掉 Eve 可能知道的 | (3.30) | [keyRateAt.m:58](+qkd/keyRateAt.m#L58) |

中间还夹着一步「统计起伏」（§2.4），它把 ②③ 的**点估计**变成**区间**，再喂给 ④。
完整顺序是：`gain` → `fluct` → `estimate`(3.28/3.29) → `keyRateAt`(3.30)。

### 3.2 任务 1：只改脉冲数 N，看能传多远

- **怎么做**：三个 `N` 各算一条曲线，参数全用题目给的（`u=0.5, v=0.1, Pu=0.6, Pv=0.3`），不优化。
- **代码**：[run_task1.m:45-50](tasks/run_task1.m#L45-L50) 造说明书 → 调 `qkd.runCase`；模式 `opt='none'`（[runCase.m:71](+qkd/runCase.m#L71)）。
- **结果（实测）**：

| N | 最远距离 Lmax | R(0) |
| --- | --- | --- |
| 1e8（一亿） | 150 km | 1.501e-2 |
| 1e9（十亿） | 176 km | 1.522e-2 |
| 1e10（百亿） | 193 km | 1.529e-2 |

- **该看懂的现象**：三条曲线在中近距离几乎重合，差别全压在「密钥率快要归零」的远端。
  原因是 §2.4 那条公式里 `N` 在分母上：近距离计数多，余量本来就很窄，`N` 大一点没感觉；
  远距离计数已经很少，余量本来就宽，`N` 一变就翻倍地影响结果。
  **一句话：有限长惩罚不是均匀的常数修正，它专门在远端咬人。**

### 3.3 任务 2：三种界比一比，顺便把光强调到最好

- **怎么做**：`N=1e9`，三种方法各算一条；每个距离点单独找最优 `u`（`opt='u'`，`mode='perDistance'`）。
- **代码**：[run_task2.m:39-47](tasks/run_task2.m#L39-L47) 造说明书；优化在 [runCase.m:83-95](+qkd/runCase.m#L83-L95)：把 61 个候选 `u` 一次算完，取最大的那个（[runCase.m:95](+qkd/runCase.m#L95)）。
- **结果（实测）**：

| 方法 | 最远距离 | R(100 km) | 100 km 处最优 u* |
| --- | --- | --- | --- |
| 高斯 Gaussian | 176 km | 1.362e-4 | 0.64 |
| 切尔诺夫 Chernoff | 164 km | 1.262e-4 | 0.62 |
| 霍夫丁 Hoeffding | 157 km | 9.089e-5 | 0.48 |

- **该看懂的两件事**：
  1. **界越紧传得越远**。高斯最宽松（余量最窄），霍夫丁最保守（不管什么分布都按最坏算），切尔诺夫居中。
  2. **最优光强随距离单调下降**（实测 165 个有效点没有一个上升）。近距离可以「开大灯」多收光子；
     远距离必须调暗——因为调亮会让多光子比例上升，单光子那部分反而估不准，安全账算不过来。
     这正好呼应 §2.2：**光强不是越大越好，它是个权衡。**

### 3.4 任务 3（提高项）：四个参数一起优化

- **怎么做**：切尔诺夫 + `N=1e9`，把 `(u, v, Pu, Pv)` 一起交给算法去搜（`opt='global'`）。
- **代码**：搜索算法在 [runCase.m:258-320](+qkd/runCase.m#L258-L320)——差分进化找大致方向，坐标下降再精修。
- **结果（实测）**：最远距离 `164 km → 171 km`；速率提升 `+49% @50 km`、`+30% @100 km`、`+14% @150 km`。
- **该看懂的三件事**：
  1. **四个参数互相牵制**：`Pu` 调大能让更多脉冲去成码，但真空态 `P0 = 1-Pu-Pv`（[params.m:79](+qkd/params.m#L79)）被挤小，暗计数就估不准；
     `v` 必须比 `u` 小，否则 (3.28) 的分母变号（[estimate.m:103](+qkd/estimate.m#L103)），整套估计直接失效。
  2. **最优参数有方向性地漂移**：远距离要抬高 `v` 和 `Pv`，才能把单光子参数估准（`verify.log` 里 `L=30 km` 时 `v*=0.044`，`L=150 km` 时 `v*=0.159`）。
  3. **收益主要在中近距离提速**，最远距离只小幅推进——因为远端受限于统计起伏，不是受限于工作点。

## 5 十处关键代码逐行导读

### ① 泊松分布：为什么「光强 0.5」还有 7.6% 的双光子

```matlab
np = @(n, l) exp(-l) .* l.^n ./ factorial(n);   % estimate.m:64
```

`np(1, 0.5)` 就是「恰好 1 个光子」的概率，`np(2, 0.5)` 是「恰好 2 个」。
`@(n, l)` 是 MATLAB 的匿名函数写法（相当于把公式变成一个可以调用的东西）。
**理解这一行，就理解了为什么必须用诱骗态。**

### ② 增益：一个脉冲「被收到」的概率

```matlab
g.Qu = p.Y0 + g.eta_u;          % gain.m:52
```

`g.eta_u = 1 - exp(-eta*u)` 是「至少来一个光子」的概率（[gain.m:47](+qkd/gain.m#L47)），
`p.Y0` 是探测器自己瞎响的概率。两者相加就是 Bob 报告「收到了」的总概率。

### ③ 高斯界的 γ：为什么是 5.33

```matlab
gamma = sqrt(2) * erfcinv(eps);   % fluct.m:77
```

`erfcinv` 是「误差函数的反函数」，用来查「要留几个标准差才够安全」。
`ε=1e-7` 时算出来 5.33——意思是：得留 5.33 个标准差，才敢说「我说错的概率只有千万分之一」。

### ④ 霍夫丁界：不猜分布，只按最坏情况

```matlab
k = sqrt(0.5 * log(1 / eps));     % fluct.m:90
```

它凭空多了一个 `sqrt(n_W)`——因为霍夫丁不等式要求「有界」这一个条件就给出保证，
代价就是余量比高斯宽。**这就是霍夫丁曲线总是最低的原因。**

### ⑤ 切尔诺夫界为什么上下不对称

```matlab
dLo  = sqrt(2 .* xobs .* log(16 ./ eps.^4));   % fluct.m:159 下界余量（宽）
dHi  = sqrt(2 .* xobs .* log(eps .^-1.5));     % fluct.m:160 上界余量（紧）
```

`16/ε⁴` 比 `ε^-1.5` 大得多，所以下界留得更宽。这不是笔误，是刻意的：
**算密钥要下界（宁可少算），算误码要上界（宁可多算），两边都取对自己不利的那一侧。**

### ⑥ 单光子响应率的下界：整个工程最重要的一行

```matlab
Y1Lz = (P2u .* QvZ_lo - P2v .* QuZ_hi + (P2v .* P0u - P2u .* P0v) .* Y0_hi) ./ den;   % estimate.m:107
```

逐项看：诱骗态增益取 `_lo`（下界）、信号态增益取 `_hi`（上界）、暗计数取 `_hi`（上界）。
每一项都在「让结果更小」。这就是安全分析的行规：**悲观到底。**

### ⑦ 单光子误码率的上界

```matlab
e1Ux = (TvX_hi - P0v .* p.e0 .* Y0_lo) ./ (P1v .* max(Y1Lx, realmin));   % estimate.m:118
```

分子：X 基收到的错误总数，扣掉真空态瞎猜的错误。分母：单光子数量取下界 → 分母小 → 结果大 → 更悲观。
（`realmin` 是最小正数，纯粹为了防「除以 0」。）

### ⑧ 当估计失效时，直接认输

```matlab
e1Ux(Y1Lx <= 0) = 0.5;   % estimate.m:124
```

如果连单光子响应率都估成负数（说明这段距离压根没密钥），就别硬算了，
按最坏情况 `e1 = 0.5`（等于纯瞎猜）处理。往下走，密钥率自然会被压到 0。
**这是「不知道就说不知道」的正确姿势。**

### ⑨ 密钥率：收入减支出

```matlab
R = p.Pu .* p.Pza_u .* p.Pzb .* ...
    (d.P1u .* Y1Lz .* (1 - H2(e1Ux)) - d.Qu .* p.f .* H2(d.Eu));   % keyRateAt.m:58-60
```

三个概率连乘是「资格系数」，括号里是「隐私放大后的收入 − 纠错开销」。
算出来负数就一律按 0 处理（[keyRateAt.m:65](+qkd/keyRateAt.m#L65)）——负的密钥率没有物理意义，只是「这段距离不行了」。

### ⑩ Lmax 是怎么定义的

```matlab
idx = find(out.R > 0, 1, 'last');   % runCase.m:214
```

「最后一个密钥率还是正数的距离点」。三个任务都在比这个数，因为它比整条曲线更好比较。
顺带一个细节：没密钥的那些点，最优参数会被置成 `NaN`（[runCase.m:206-210](+qkd/runCase.m#L206-L210)），
这样参数曲线会自然断开，而不是画出一段毫无意义的跳变。

## 6 初学者最容易问的八个问题

**Q1：为什么诱骗态必须比信号态弱（u > v）？**
看分母 `P1v·P2u - P1u·P2v`（[estimate.m:103](+qkd/estimate.m#L103)）。这个式子在 `u > v` 时恒为正；
一旦 `v > u` 就变号，算出来的 `Y1` 是负数，被截成 0，整段距离直接没密钥。

**Q2：为什么密钥率会「突然掉到 0」？**
不是算错了，是物理上到头了。距离一远，暗计数盖过真实信号，`Y1` 下界掉到 0，
于是 `e1` 只能按最坏值 0.5 处理，`1 - H2(0.5) = 0`，收入变成 0，减去纠错开销就是负数，截断为 0。

**Q3：为什么 ε 取 1e-7？**
课程指导书就是这么定的，对应高斯界里的 `γ ≈ 5.33`。`ε` 越小越安全，但余量越宽、传得越近。
你可以自己改成 `1e-9` 试一下，会看到三条曲线整体缩短。

**Q4：高斯界最宽松，为什么还最常用？**
因为它最紧（性能最好），但严格来说它依赖「大样本近似正态」这个前提，不是严格的有限长安全证明；
霍夫丁、切尔诺夫是有严格不等式保证的，代价是保守。工程上常见做法是：**先用高斯看性能上限，再用严格界验证可行性。**

**Q5：为什么优化 `Pu` 会影响 `P0`？**
三种脉冲的概率必须加起来等于 1，所以 `P0 = 1 - Pu - Pv`（[params.m:79](+qkd/params.m#L79)）。
代码在优化时会同步重算 `P0`（[runCase.m:236](+qkd/runCase.m#L236)），否则三种强度就不归一了，物理上自相矛盾。

**Q6：为什么 `e1` 最大只到 0.5？**
误码率超过 0.5 意味着「全反过来理解反而更准」——那是没有信息的，等价于 0.5。
代码里 `min(max(e1Ux,0),0.5)` 这一句（[estimate.m:119](+qkd/estimate.m#L119)）就是在做这个夹取。

**Q7：密钥率的单位为什么是 bit/pulse，不是 bit/s？**
因为它算的是「每个脉冲平均能剩下多少比特密钥」，跟硬件发多快无关。要换算成速率，
乘上系统的脉冲重复频率（比如 1 GHz）就行。

**Q8：为什么优化器用「差分进化」这种听起来很玄的算法？**
因为目标函数 `R(u,v,Pu,Pv)` 非凸、有约束（`v<u`、`Pu+Pv≤0.95`）、还没有解析导数，梯度法用不了。
差分进化的好处是「撒一群点、好的留下」，不需要导数（代码 [runCase.m:280-294](+qkd/runCase.m#L280-L294)）；
它擅长找方向、不擅长抠精度，所以最后再用坐标下降打磨一下（[runCase.m:305-320](+qkd/runCase.m#L305-L320)）。

## 7 自己动手：五个由浅入深的实验

每个实验都给了「预期现象」，做完对照一下，比看十遍书有用。

**实验 1：换一根更好的光纤**
把 [params.m:61](+qkd/params.m#L61) 的 `alpha` 从 `0.2` 改成 `0.18`（损耗更小），跑 `runTests`。
→ 预期：会有一批断言变红。**这不是你弄坏了，而是物理确实变了**——这正是「金标准」存在的意义。
再跑 `run_task1`，会看到 `Lmax` 明显变远。

**实验 2：把安全要求提高两个数量级**
把 `spec` 里的 `eps` 从 `1e-7` 改成 `1e-9`，跑 `run_task2`。
→ 预期：三条曲线整体缩短、整体下移。因为「说错的概率」要求更严，余量必须留更宽。

**实验 3：换一个更吵的探测器**
把 `d`（暗计数）从 `1e-6` 改成 `1e-4`，跑 `run_task1`。
→ 预期：远端塌得更早。暗计数变大后，`Y0` 上界变宽，`Y1` 下界被压得更低。

**实验 4：把「逐距离优化」改成「全程统一优化」**
把 [run_task2.m:41](tasks/run_task2.m#L41) 的 `'mode', 'perDistance'` 改成 `'mode', 'fixed'`，跑一遍。
→ 预期：曲线整体下降。这就是「实际系统不能按距离重标定」要付的代价。
代码走的是 [runCase.m:103-116](+qkd/runCase.m#L103-L116) 那条分支。

**实验 5（进阶）：加一种新的统计界**
在 [fluct.m](+qkd/fluct.m) 的 `switch` 里照着 `hoeffding` 那一支再加一个 `case`，写你自己的余量函数。
→ 学会这一步，你就掌握了这个工程最重要的设计：**三种方法只差一个偏差函数，其余代码一行都不用改。**
