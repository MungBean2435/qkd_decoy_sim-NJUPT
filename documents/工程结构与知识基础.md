### 1.2 分层：谁可以调谁

```
   界面层            QKDApp.m            tasks/run_task1..3.m        checks/*.m
   （只收集/展示）        \                    |     |                 /
                          \                   |     |                /
                           v                  v     v               v
   接口层  ──────────────────────────  qkd.runCase  ──────────────────────────
                                       （唯一计算入口）
                                              |  调用
                                              v
   物理层                            qkd.keyRateAt ──(3.30)──> 单个距离点的 R
                                        |            \
                                        v             v
                                 qkd.estimate     二进制熵 H2
                                    |      \
                                    v       v
                            qkd.gain     qkd.fluct（三种尾部界）

   支撑层      qkd.params（参数表）   tools/newFig·saveResult·cjkFont（只管画和存）
```

三条依赖规则（读代码时按这个判断「这段该不该在这里」）：

1. **物理公式只能出现在 `+qkd/` 里**。`tasks/`、`QKDApp.m` 若出现 `exp(-eta*u)` 之类的式子，就是分层被破坏了。
2. **依赖方向单向向下**：界面层 → `runCase` → `keyRateAt` → `estimate` → `gain`/`fluct`。反过来的调用（内核去调 GUI）一处都不存在，所以内核能被 `checks/` 无窗口驱动。
3. **`tools/` 不属于物理链**：它只在「准备画图/存盘」时被调用，删掉它不影响任何数值。

### 1.3 一次计算的完整数据流

以「切尔诺夫方法、N=1e9、L=100 km」为例，调用链是：

```
qkd.runCase(p, spec)                         ← spec 描述「算什么」
  └─ 对每个距离点 i：
       rateFor(p, L(i), spec, u, v, Pu, Pv)  ← 把待优化的参数写回 p 的副本
         └─ qkd.keyRateAt(q, L, spec)        ← (3.30)
              ├─ qkd.estimate(q, L, spec)    ← (3.28)(3.29)：Y1L、e1U
              │    ├─ qkd.gain(q, L)         ← η、Q_u、Q_v、E_u、E_v、T_v
              │    └─ qkd.fluct(method, eps) ← 把「观测值」变成「置信区间」
              │         （返回 D.Q / D.T / D.Y0 三个句柄）
              └─ 二进制熵 H2 → 成码项 − 纠错项 → R
```

链上有一个设计要点值得学：**`fluct` 返回的是一组函数句柄**（`D.Q`、`D.T`、`D.Y0`），不是一个数。于是三种起伏方法被压缩成「同一个接口、不同实现」，`estimate.m` 完全不需要 `if method == 'gauss' ... else ...`。这就是函数式编程里的**策略模式（strategy pattern）**，在 MATLAB 里用匿名函数加闭包实现：`gaussBound` 需要的 `gamma` 在创建句柄时按值捕获。

## 2 解决的三个问题

三个任务共用同一套物理场景与同一条计算链，**区别只在「哪些参数固定、哪些参数被优化」**。所以先看共同部分，再看三个任务的差异，最后看三张图合起来的物理结论。

### 2.0 共同场景

- **协议**：三强度诱骗态 BB84。Alice 用弱相干光源（WCS，衰减后的激光脉冲）发送三种强度：信号态 `u`、诱骗态 `v`、真空态（概率 `P0 = 1 − Pu − Pv`）。
- **两个基**：Z 基用于**成码**（生成密钥），X 基用于**参数估计**（估单光子误码率）。所以 Alice 在每种强度下还要按 `P^A_{Z|u}` 等概率选基。
- **Bob**：单光子探测器，探测效率 `η_d`、暗计数 `d`；光纤损耗 `α = 0.2 dB/km`；系统本底误码 `e_d = 0.015`。
- **输出**：安全密钥率 `R(L)`，单位 bit/pulse；以及最远成码距离 `Lmax`（最后一个 `R > 0` 的距离点）。

参数表（`+qkd/params.m`，与题目表 1 逐项对应）：

| 符号 | 代码字段 | 值 | 物理含义 |
| --- | --- | ---: | --- |
| `u` | `p.u` | 0.5 | 信号态光强（平均光子数） |
| `v` | `p.v` | 0.1 | 诱骗态光强 |
| `Pu` / `Pv` | `p.Pu` / `p.Pv` | 0.6 / 0.3 | 信号态 / 诱骗态选择概率 |
| `P0` | `p.P0` | 0.1 | 真空态概率（由归一化 `1 − Pu − Pv` 给出） |
| `P^A_{Z\|u}`, `P^A_{Z\|v}` | `p.Pza_u`, `p.Pza_v` | 0.5 | Alice 在两种强度下选 Z 基的概率 |
| `P^B_Z` | `p.Pzb` | 0.5 | Bob 选 Z 基的概率 |
| `f` | `p.f` | 1.16 | 纠错效率（1.0 = 理论上限，1.16 = 实际实现） |
| `α` | `p.alpha` | 0.2 dB/km | 光纤损耗系数 |
| `η_d` | `p.etad` | 0.5 | Bob 端探测效率 |
| `d` | `p.d` | 1e-6 | Bob 端暗计数（每脉冲） |
| `e_d` | `p.ed` | 0.015 | 系统本底误码率 |
| `e_0` | `p.e0` | 0.5 | 真空态误码率（猜硬币） |
| `Y_0` | `p.Y0` | ≈2e-6 | 真空态响应率，`Y0 = 2d(1−d)`（两个探测器任一响即触发） |
| `η_A`, `d_A` | `p.etaA`, `p.dA` | — | HSPS 本地探测器参数，三强度 WCS 场景**不使用**（保留字段） |

### 2.1 任务 1：高斯起伏 + 不优化（基线）

| 项 | 内容 |
| --- | --- |
| 题目要求 | 高斯型统计起伏下，发射脉冲数 `N = 1e8 / 1e9 / 1e10`，**不优化**，画 `R–L` |
| 口径 | `method='gauss'`，`opt='none'`，`u=0.5, v=0.1, Pu=0.6, Pv=0.3` 全部沿用题目给定值，`ε=1e-7`，`L = 0:1:300 km` |
| 脚本 | `tasks/run_task1.m` → `results/fig1_gauss_threeN.{png,csv,fig}` |
| 实测结果 | `N=1e8` → `Lmax=150 km`，`R(0)=1.501e-2`；`N=1e9` → `176 km`，`1.522e-2`；`N=1e10` → `193 km`，`1.529e-2` |
| 看点 | 三条曲线在**中近距离几乎重合**，差异全部压在「密钥率将要归零」的远端。原因：`R(0)` 附近计数大、统计误差相对小，有限长惩罚只体现为一点绝对偏差；而远端计数量级骤降，罚项反而成为主导，直接把 `Lmax` 拉开 43 km |

这道题真正想让人理解的是：**有限长效应不是均匀的常数修正，而是随计数量下降而急剧放大**。

### 2.2 任务 2：三种起伏方法 + 优化信号态光强

| 项 | 内容 |
| --- | --- |
| 题目要求 | `N = 1e9` 时，高斯 / 霍夫丁 / 切尔诺夫三种方法，**优化信号态 `u`** 后画 `R–L` |
| 口径 | `opt='u'`，`optU = {lb 0.10, ub 1.30, n 61, mode 'perDistance'}`；`v, Pu, Pv` 仍固定 |
| 优化含义 | **逐距离最优**：每个距离点独立取使 `R` 最大的 `u*`（61 个候选网格上取 argmax），不是一条曲线用一个 `u` |
| 脚本 | `tasks/run_task2.m` → `fig2_three_methods.*`（`R–L` 对比）+ `fig2b_optimal_u.*`（`u*(L)` 演化） |
| 实测结果 | 高斯 `Lmax=176`, `R(100)=1.362e-4`, `u*(100)=0.64`；霍夫丁 `157`, `9.089e-5`, `u*(100)=0.48`；切尔诺夫 `164`, `1.262e-4`, `u*(100)=0.62` |
| 看点 | ① 高斯界最宽松（中心极限定理在 `N` 大时最贴合真实分布）、霍夫丁最保守（无分布假设、最坏情况界）、切尔诺夫居中；② `u*(L)` 随距离**单调下降**（实测：切尔诺夫曲线 165 个有效点中，上升步数 = 0，从 `u*(0)=0.74` 一路降到远端 0.48）——近距离光强可以放大以提增益，远距离必须压低单光子概率，否则多光子项被诱骗态估计出来的上界压死 |

为什么允许「逐距离优化」：实际系统里工作点本来就可以按链路长度标定；这条曲线因此是**该方法的性能上限**，包住所有固定 `u` 的结果。这也解释了图2 的曲线为什么比图1 更靠上（图1 用的是题目给定 `u=0.5`，而 100 km 处最优是 0.62~0.64）。

### 2.3 任务 3（提高项）：切尔诺夫 + 四参数全局优化

| 项 | 内容 |
| --- | --- |
| 题目要求 | 切尔诺夫起伏下，`N = 1e9`，**全局优化** `(u, v, Pu, Pv)` 后画 `R–L`，并与不优化对比 |
| 口径 | `opt='global'`，`optG = {npop 30, ngen 40}`；差分进化 + 坐标下降精修；`strideL=5` 粗网格优化后把**参数**插值回 1 km 网格重算 |
| 脚本 | `tasks/run_task3.m` → `fig3_chernoff_global.*`（优化前后对比）+ `fig3b_optimal_params.*`（四个最优参数随距离演化） |
| 实测结果 | 未优化 `Lmax=164 km`；全局优化后 `Lmax=171 km`（与 README 一致）；速率提升 `+49% @50 km`、`+30% @100 km`、`+14% @150 km` |
| 看点 | ① 四个参数存在**权衡**：拉高 `Pu` 能提高成码脉冲占比，但真空态概率 `P0 = 1−Pu−Pv` 被挤压，`Y0^U` 估计变坏；② 最优参数随距离**有方向性地漂移**：近距离偏大 `u`、小 `v`；远距离要抬高 `v` 与 `Pv` 才能把单光子参数估准（`verify.log` 里 `L=30 km` 时 `v*=0.044`，`L=150 km` 时 `v*=0.159`）；③ 工程上不必逐公里做四参数搜索——「粗网格优化 + 插值参数」把 301 点降到 61 点，代价只是曲线**略偏保守**（因为插值出来的参数对该点未必最优） |

**这是三个任务里唯一需要「优化算法」知识的**：目标函数 `R(u,v,Pu,Pv)` 非凸、有物理约束（`v < u`、`Pu+Pv ≤ 0.95`、都 > 0）、单次评估要跑完整条估计链，所以选**差分进化**（无梯度、适合非凸、天然可并行评估）再用坐标下降收尾。

### 2.4 三张图合起来的结论

1. **有限长惩罚是「远端现象」**：`N` 从 `1e8` 到 `1e10`，`Lmax` 150 → 193 km，但曲线在中近距离几乎不动（任务 1）。
2. **界越紧，成码越远**：同一 `N` 下高斯 176 km > 切尔诺夫 164 km > 霍夫丁 157 km（优化 `u` 后，实测）；界越松 → 为达同一安全水平需扣掉更多量 → 最远距离越短。
3. **参数优化能换回可观的距离与速率**：全局优化把切尔诺夫从 164 km 推到 171 km，速率 `+49% @50 km / +30% @100 km / +14% @150 km`（任务 3）——收益主要在「中近距离提速」，最远距离只能小幅推进。
4. 换句话说：**同一个物理场景，安全结论完全取决于「统计界」与「工作点」两个建模选择**——这正是有限长 QKD 分析的核心。

## 3 涉及的知识基础

按「读代码时会撞到」的顺序组织。每条都给「概念 → 代码位置 → 需要理解到什么程度」。

### 3.1 BB84 协议与 QKD 的基本逻辑

- **制备–测量**：Alice 在 Z 基 `{|0>, |1>}` 或 X 基 `{|+>, |−>}` 里随机编码，Bob 随机选基测量，事后公开比对基，只保留同基事件（筛选）。
- **为什么两个基**：Z 基的比特用来**成码**，X 基几乎不用来成码，专门用来**估误码**——因为攻击者若窃听 X 基会留下误码痕迹，用 X 基的统计量给 Z 基的安全性定界（这就是「参数估计」）。
- 代码位置：`p.Pza_u`、`p.Pza_v`、`p.Pzb` 决定基选择权重；`estimate.m` 里 Z 基算密钥、X 基算 `e1U`。

### 3.2 弱相干光源（WCS）与光子数分裂攻击 → 为什么必须用诱骗态

- 理想单光子源每次恰好一个光子；实际用衰减激光，光子数服从**泊松分布** `P_n^l = e^{-l} l^n / n!`（代码：`estimate.m` 的 `np = @(n,l) exp(-l).*l.^n./factorial(n)`）。
- 于是总有概率发出 ≥2 个光子（`u=0.5` 时 `P_2 ≈ 7.6%`）。**光子数分裂（PNS）攻击**：Eve 把多光子态拿走一份，等 Bob 测量后据公开基信息补齐，全程不引入误码。
- 所以直接用 WCS 的 QKD 在长距离上**没有安全密钥**。对策不是换光源，而是**诱骗态**：随机切换光强，让 Eve 无法判断某个脉冲是否多光子，从而用不同强度的增益联立方程，把「单光子」的贡献**分离估计**出来。

### 3.3 三强度诱骗态：线性方程组与上下界

要算密钥率，只需要两个单光子量：响应率 `Y1`（下界）和误码率 `e1`（上界）。但观测到的只有各强度的总增益 `Q_u, Q_v` 和总误码 `E_u, E_v`。三强度方案用「信号 + 诱骗 + 真空」写出方程并解出保守估计：

- **(3.28) 单光子响应率下界**
  `Y~1^{W,L} = [P_2^u Q_v^L − P_2^v Q_u^U + (P_2^v P_0^u − P_2^u P_0^v) Y_0^U] / (P_1^v P_2^u − P_1^u P_2^v)`
  分母恒正（因为 `u > v`），这就是**光强必须满足 u > v** 的数学原因；`Q_v` 取下界、`Q_u` 取上界、`Y_0` 取上界——每一步都朝「让 `Y1` 更小」的方向取，保证结论安全。
- **(3.29) 单光子误码率上界**
  `e~1^{X,U} = (T_v^U − P_0^v e_0 Y_0^L) / (P_1^v Y~1^{X,L})`
  同样：分子取「让 `e1` 更大」的方向；`Y1Lx ≤ 0` 时无法估计，直接取最坏值 `e1 = 0.5`（代码里这一行为 `e1Ux(Y1Lx <= 0) = 0.5`）。

代码：`+qkd/estimate.m` 第 101–124 行，几乎逐项对应上面两式，可以拿公式对着读。

### 3.4 光纤信道与探测器模型

- **损耗的 dB 记法**：`η = η_d · 10^(−αL/10)`。`α = 0.2 dB/km` 意味着每 50 km 损耗 10 dB、透过率降一个数量级；100 km 后 `η ≈ 0.5 × 10^-2`。
- **增益**：`Q_l = Y_0 + 1 − e^{−η l}`。`1 − e^{−ηl}` 是「至少一个光子到达并被探测」，`Y_0` 是暗计数贡献。
- **误码率**：`E_l = (e_0 Y_0 + e_d (1 − e^{−η l})) / Q_l`，即「真空态猜错 + 真实光子本底误码」加权平均。
- **误码计数**：`T_l = E_l Q_l`（代码 `g.Tu/g.Tv`）——因为 Chernoff/Hoeffding 界是对**计数**定的，不是对率。
- 代码：`+qkd/gain.m` 去掉注释其实只有 12 行代码，是理解「模型有多简单」的最好例子。

### 3.5 有限长效应与三种尾部界

真实系统只发有限个脉冲 `N`，观测增益 `Q*` 是随机变量而非期望值 `Q`。要给出**失败概率不超过 ε**（`ε = 1e-7`）的置信区间，三种方法给出不同宽度的区间——**这就是三个任务的物理差异来源**：

| 方法 | 偏差形式 | 直觉 | 代码 |
| --- | --- | --- | --- |
| **高斯** | `Δ = γ√(Q/N)`，`γ = √2·erfcinv(ε) ≈ 5.3` | 中心极限定理：计数大时近似正态；`N` 大时最紧，但严格来说需要大样本前提 | `gaussBound` |
| **霍夫丁** | `\|ΔQ\| = √(n_W ln(1/ε)/2) / N` | 只需「有界随机变量」假设，最保守、最坏情况界 | `hoeffBound` |
| **切尔诺夫** | 下界 `Δ = √(2x ln(16/ε^4))`，上界 `Δ̂ = √(2x ln(ε^-1.5))` | 泊松计数专属的乘性界；**上下界不对称**（下界更宽、上界更紧） | `chernoffBound` |

要理解的三点：
1. `N` 出现在分母 → `N` 越大区间越窄，这就是任务 1 里 `N` 增大使 `Lmax` 变远的机制。
2. `ε` 越小 `γ` 越大 → 安全要求越高，区间越宽、距离越短。`ε=1e-7` 对应指导书 `γ = 5.3`。
3. 切尔诺夫界不对称是刻意的：估 `Y1` 要用 `Q_v` 的**下界**（保守），估 `e1` 要用 `T_v` 的**上界**（保守），两个方向都用「对自己不利」的那一侧。

工程上的妙处（§1.3 提过）：`fluct.m` 把三种方法统一成 `D.Q / D.T / D.Y0` 三个句柄，所以 `estimate.m` 里**一行 `if` 都没有**——「三种方法只差一个偏差函数」。

### 3.6 安全密钥率公式 (3.30) 逐项

```
R ≥ P_u · P^A_{Z|u} · P^B_Z · { P_1^u · Y~1^{Z,L} · [1 − H2(e~1^{X,U})]  −  Q_u · f · H2(E_u) }
    └──── 权重：多大概率真的在用信号态 + 双 Z 基 ────┘  └──── 成码（隐私放大后）────┘   └─ 纠错开销 ─┘
```

- `H2(x) = −x log2 x − (1−x) log2(1−x)`：二进制熵（代码 `keyRateAt.m` 第 54 行的匿名函数）。
- 第一项 `P_1^u Y1L [1 − H2(e1U)]`：单光子贡献，扣掉 Eve 可能掌握的信息。
- 第二项 `Q_u f H2(E_u)`：**纠错**要公开的比特量，`f = 1.16` 表示比香农极限多花 16%。
- `R < 0` 截断为 0（无正密钥即不通信），`R` 非有限也置 0。
- 想再往深处走，可以顺着这条式子去找 **Devetak–Winter 定理 / GLLP 公式**：它把「协议安全性」转化为「单光子参数的下界」，这是整套推导的骨架。

### 3.7 优化：从网格搜索到差分进化

| 层级 | 用在何处 | 知识点 |
| --- | --- | --- |
| 一维网格扫描 | `opt='u'`：61 个候选 `u`，逐距离取 `argmax` | `linspace`、向量化评估（`rateFor` 支持向量输入） |
| 差分进化 DE | `opt='global'`：4 维 `(u, v/u, Pu, Pv)` | 变异 `mut = x_r1 + F(x_r2 − x_r3)`，`F=0.6`；交叉 `CR=0.7`；按「整代」批量评估（一次 `keyRateAt` 算 `npop` 个候选） |
| 边界与约束 | `lb=[0.1,0.02,0.05,0.02]`、`ub=[1.4,0.9,0.9,0.9]`；`objFun` 里违反 `v<u`、`Pu+Pv≤0.95` 者直接置 0（惩罚法） | 有约束非凸优化的工程做法 |
| 坐标下降精修 | DE 之后在最优附近 ±step 试探，30 轮、步长逐次减半 | 局部搜索收尾，补足 DE 的收敛精度 |
| 降维技巧 | 优化变量用 `v/u` 比值而非 `v` 本身，天然保证 `v < u` 的方向感 | 参数化方式比加约束更省事 |
| 可复现 | `rng(20260101)` 固定种子 | 随机算法必须固定种子，否则数值不可回放 |

另外 `runCase.m` 里有个**性能工程**技巧：全局优化单点代价约是普通扫描的千倍，而相邻距离点最优参数几乎连续，于是「5 km 粗网格优化 → 把**参数**（不是曲线）插值回 1 km 网格重算 → 断崖处按原网格补优化」。注意插值的是参数：每个细点都是**真算**出来的，只是参数对该点未必最优，所以曲线略偏保守。这是「近似要能说清偏在哪个方向」的好例子。

### 3.9 数值稳健性与回归测试

- **防除零**：`N = max(N, realmin)`（`fluct.m`）、分母 `max(Y1Lx, realmin)`（`estimate.m`）。
- **截断到物理可行域**：`R<0 → 0`、`e1 ∈ [0, 0.5]`、`Q_lo = max(x−Δ, 0)`、`Y1L = max(Y1L, 0)`。
- **无密钥区不画无意义跳变**：`R ≤ 0` 处把最优参数置 `NaN`（`runCase.m` 206–210）。
- **金标准回归**：`checks/runTests.m` 把 `R(0), R(50), R(100), Lmax` 写成硬编码基准（容差 `1e-9`），改物理模型必须同步更新——否则「改了」和「改坏了」无法区分。这是课程设计里最容易被忽略、但答辩最容易被问的一环。
- **合理性断言**：优化不得劣于基准（`oU.R ≥ oB.R*0.999`）、`Lmax` 随 `N` 单调增、超远距离 `R` 有限且非负——不验数值，验**物理方向**。

### 3.10 术语速查

| 术语 | 含义 |
| --- | --- |
| WCS | Weak Coherent Source，弱相干光源（衰减激光），光子数服从泊松分布 |
| 诱骗态 decoy state | 随机切换光强，逼迫 Eve 无法区分多光子脉冲，从而估出单光子参数 |
| PNS 攻击 | Photon Number Splitting，分走多光子脉冲中的多余光子而不引入误码 |
| `Y1` / `e1` | 单光子响应率 / 单光子误码率；密钥率公式需要的两个量 |
| `Q_l` / `E_l` / `T_l` | 强度 `l` 的总增益 / 量子误码率 / 误码计数 |
| 有限长效应 | 因脉冲数有限，观测值与期望值有统计偏差，需用置信区间定界 |
| `ε` (eps) | 失败概率（安全参数），越小越安全、区间越宽 |
| `Lmax` | 最远成码距离：最后一个 `R > 0` 的距离点 |
| Z 基 / X 基 | 成码基 / 参数估计基 |
| 逐距离优化 | 每个距离点单独取最优参数（曲线是该方法性能上限） |
| 粗网格 + 插值参数 | 先在粗网格上优化，再把参数插值到细网格重算（略偏保守） |

## 4 建议的阅读 / 学习顺序

按「先看结论 → 再看模型 → 最后看工程」的顺序，大约 3 小时可以吃透：

1. `README.md` §一、§三：先看三张图和结论表，建立物理图像。
2. `+qkd/params.m`（81 行）：把参数表和题目对应起来，弄清每个符号。
3. `+qkd/gain.m` → `+qkd/keyRateAt.m`：最短的一条链，先接受「损耗→增益→误码」的模型。
4. `+qkd/fluct.m`：三种界，重点看**为什么三种方法只差一个偏差函数**。
5. `+qkd/estimate.m`：拿 (3.28)(3.29) 逐行对照，理解「每一步都往坏处取」。
6. `+qkd/runCase.m`：编排逻辑 + DE + 粗网格插值，这是全工程最「工程」的文件。
7. `tasks/run_task1.m`：最简出图脚本，学 `newFig`/`saveResult`/`onCleanup` 的用法。
8. `QKDApp.m`：想看 GUI 时再读，它只是「收集 spec → 调 runCase → 画图」的放大版。
9. 动手改一处再自检：例如把 `params.m` 的 `α` 从 0.2 改到 0.18，跑 `runTests` 看哪几项变红（这就是「物理改动必然打破金标准」的体感）。

**发现一处文档与实测不一致：**
